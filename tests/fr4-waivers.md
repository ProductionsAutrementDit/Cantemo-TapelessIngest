# FR-4 equivalence waivers

FR-4 requires the refactored pipeline to behave equivalently to the legacy
one. Every DELIBERATE, signed-off divergence is declared here — one row per
behavioral delta, added by the story that introduces it, together with the
pinning-test update and the `tests/pinned-bugs.md` row it retires.

A delta absent from this table is a regression, not a decision.

| FR | story | date | behavioral delta |
|----|-------|------|------------------|
| FR-10 | 2.4 | 2026-08-21 | Scan now materializes `Clip`/`ClipMetadata` rows for never-ingested clips (a hash-recovered `item_id` therefore lands on the row at scan time instead of at ingest time). Pre-2.4 only an already-saved clip's metadata was written, per key, by the `metadatas` setter. |
| FR-10 | 2.4 | 2026-08-21 | Re-scanning a never-ingested folder reports `created=0` instead of re-counting the same N clips on every run — the first scan now persists them. More honest; the FR-4 counter tuples of a first scan are unaffected. Pinned by `tests/tier2/test_persistence_write_unit.py::test_rescan_never_ingested_reports_created_zero`. |
| FR-11 | 2.4 | 2026-08-21 | A dry-run scan no longer writes the `Folder` row nor an existing clip's metadata rows. Pre-2.4 `dry_run` gated only `Folder.ingest`'s ingest block, so a "dry" run still wrote both. Directionally FR-11; full dry-run purity is story 2.7. Pinned by `tests/tier2/test_persistence_write_unit.py::test_dry_run_scan_writes_nothing`. |
| FR-23 | 2.5 | 2026-08-21 | `already_ingested` now counts clips whose `item_id` is truthy (post hash-recovery) instead of every clip the page processed. Pre-2.5 it counted `clip.file is not None`, which the scan sets for every clip it touches, so the counter reported the page size. Reported values drop for folders of never-ingested clips; the ingest counters are unaffected. Pinned by `tests/tier2/test_scan_counters.py::test_single_page_scan_counters`. |
| FR-8 | 2.5 | 2026-08-21 | A file Cantemo has not hashed yet is SKIPPED with a logged retry-next-run reason instead of raising `TapelessIngestException("No hash found in file …")`. Pre-2.5 the exception cost the file its clip, its metadatas and its scan record, and appeared in `errors`; it is now scanned normally, counted `skipped` by the ingest ladder, never matched against a legacy storage and never ingested (NFR-1 ruling: the hash is the dedup key, ingesting without it risks a duplicate item). The next cron run retries it once the hash exists. Pinned by `tests/tier2/test_ingest_discipline.py::test_hash_less_file_is_skipped_with_a_retry_reason`. |
| FR-8 | 2.5 | 2026-08-21 | A recovered `item_id` is now assigned to PRE-EXISTING clip rows as well, not only to rows being created. Recovery fires only when the clip has no `item_id`, so it can never overwrite a known one. Since the 2.4+2.5 review round the scan also PERSISTS it, through a fill-only-NULL statement of its own (`PersistencePlan.recovered_item_ids`) rather than through `CLIP_UPDATE_FIELDS`: the ingest ladder skips a clip the moment its `item_id` is truthy, so `Clip.ingest` — the other writer of that column — is never reached for exactly these clips, and the id would have been recovered again on every future scan. Pinned by `tests/tier2/test_ingest_discipline.py::test_recovery_assigns_the_item_id_to_a_pre_existing_row`, `::test_a_recovered_item_id_is_persisted_on_the_row`, `::test_a_second_scan_no_longer_pays_the_recovery_lookup` and `::test_a_recovered_id_never_overwrites_an_id_the_row_already_has`. |
| FR-35 | 2.5 | 2026-08-21 | `_should_replace_original_files` no longer auto-skips every non-replace call: the guard was `len(original_files) >= 0`, always true. An item whose original shape holds NO file now falls through to the remaining checks (same file id / same storage / non-legacy storage) instead of being declared already-imported. Reachable ONLY on the incomplete-import retry path below (with `replace=False` and no retry, `import_file` returns at the "item already exists" rung before this function is called; with `replace=True` the guard's own `replace == False` conjunct short-circuits it). Pinned by `tests/tier1/test_scan_ingestion.py::test_empty_original_files_no_longer_auto_skips` and, end to end, `tests/tier2/test_ingest_discipline.py::test_an_empty_original_shape_does_not_block_the_retry`. |
| FR-36 | 2.5 | 2026-08-21 | A clip whose import created a placeholder but started no job (`item_id` set, `job_id` NULL, status `Placeholder created`) is RE-INGESTED on the next run instead of being skipped as already-ingested forever. The retry passes `retry_incomplete=True`, which lifts `import_file`'s blanket "item already exists" early return and nothing else — an item that really holds original files still comes back `skipped`, and the same placeholder is reused rather than a second one created. Deliberately narrower than "item_id without job_id": a HASH-RECOVERED id has no job either, and retrying those would buy back the per-clip HTTP cost FR-8 removed. Pinned by `tests/tier2/test_ingest_discipline.py::test_an_incomplete_import_is_retried_next_run_not_skipped_forever`, `::test_a_recovered_item_id_is_not_mistaken_for_an_incomplete_import` and `::test_an_item_that_already_holds_the_file_is_not_re_imported`. |
| FR-23 | 2.5 | 2026-08-21 | Two scanned files resolving to ONE umid produce one ingest, not two. The umid is the clip's primary key, so they are one clip by definition; the write side already collapsed them (`dedupe_candidates`) while the ingest side did not. `created` likewise counts a umid once even when its files span two pages. The scan RESPONSE still reports every file, unchanged. Pinned by `tests/tier2/test_ingest_discipline.py::test_two_files_one_umid_are_ingested_once` and `::test_a_umid_spanning_two_pages_is_created_once`. |
| FR-10 | 2.5 | 2026-08-21 | `Clip.ingest` writes back only `INGEST_STATE_FIELDS` (`item_id`, `job_id`, `status`, `file_id`, `user`) where the deleted full `save()` wrote every column. For an EXISTING clip whose scanned file changed provider or reference file, an ingest therefore no longer rewrites `provider_name`/`reference_file` (nor location columns, which the scan deliberately never rewrites either). Everything `import_file` mutates is in the list; the dropped columns are ones only a scan produces. Pinned by `tests/tier2/test_ingest_discipline.py::test_ingest_writes_only_ingest_state_columns`. |
| FR-12 | 2.4 | 2026-08-21 | A non-empty `clip_xml` is authoritative and is never re-read from the card: a CORRECTED sidecar on disk is ignored for the life of the row (only deleting the column, or the clip, re-reads it). That is the point of the column — the pre-2.4 property re-read and re-parsed the sidecar on every save — but it is a real behavioral delta, not just a cache. Pinned by `tests/tier2/test_persistence_write_unit.py::test_a_stored_clip_xml_is_never_re_read_from_the_card`. |
| FR-27 | 2.4 | 2026-08-21 | Duplicate `Folder` rows (the NULL-`storage_id` loophole in the unique constraint) no longer raise `MultipleObjectsReturned` out of `get_or_new`: the first row by pk is returned with a WARNING. If the duplicates vanish between the failed `get()` and the retry read, a new unsaved instance is returned rather than `None`. Pinned by `tests/tier2/test_persistence_write_unit.py::test_duplicate_folder_rows_resolve_first_by_pk`. |
| FR-28 | 2.6 | 2026-08-21 | An unresolvable storage no longer raises `AttributeError` out of the run. `Folder.root_path` returns `None` when `browse_root_path` cannot resolve one (pre-2.6 `_root_path` was simply left unassigned), so `absolute_path` is falsy and the folder returns a NORMAL response carrying `Cannot get full path from storage {id}, path {path}`. Covers BOTH deltas: `Folder(storage_id=None)` and a context whose storage is unresolvable (`root_path=None` → property-chain fallback). The recursion reports the same message and stops at that folder instead of calling `os.scandir(False)`. Pinned by `tests/tier1/test_scan_pagination.py::test_storage_none_reports_cannot_get_full_path` and `tests/tier1/test_scan_adapters.py::test_scan_with_ctx_miss_falls_back_to_property_chain`. |
| FR-24 | 2.6 | 2026-08-21 | The recursion no longer descends into SYMLINKED subdirectories. It lists children through `FolderListings.dirs`, which is built with `follow_symlinks=False` (story 2.2's cycle guard), where the pre-2.6 `os.scandir` loop used `entry.is_dir()`, which follows links. A symlink loop can no longer make the walk recurse forever, and a symlinked card folder is scanned once — through its real path — instead of once per link pointing at it. |
| NFR-5 | 2.6 | 2026-08-21 | `Folder.scan`/`Folder.ingest` responses carry a new `consumed_subdirs` key (FR-19): the immediate child names this folder's clips consumed, or `None` for DOUBT ("descent is not authorized for this folder"). Purely ADDITIVE — no pre-existing key is renamed, removed or changed — so the frozen key-set pins were extended rather than broken: `tests/tier2/test_scan_counters.py`, `tests/tier2/test_scan_once_per_run.py`, `tests/tier2/test_scan_verification_integration.py`, `tests/tier1/test_scan_pagination.py`. |
| FR-11 | 2.7 | 2026-08-21 | Dry-run ingest counters report WOULD-BE outcomes instead of baseline zeros. The 2.5 ladder is pure, so it now runs and is COUNTED in both modes: `skipped` carries the ladder's rejections (item_id-bearing with `replace=False`, hash-less) and `ingested` is `len(to_ingest)` — every clip the run would have submitted, replacements included. `failed`, `replaced` and the share of `skipped` that `Clip.import_file` decides on its own remain 0 STRUCTURALLY, because no submission occurs; whole-dict equality with a real run is NOT claimed. The relation is: dry-run `ingested` is an upper bound on a real run's, dry-run `skipped` a lower bound, coinciding exactly when every submission succeeds. Supersedes the `<frozen-after-approval>` dry-run boundary of approved spec 2.5 ("skipped/ingested/failed/replaced stay 0,0,0,0 (2.7 boundary)"), recorded in both specs' Spec Change Logs. Pinned by `tests/tier2/test_dry_run_purity.py::test_dry_run_counters_match_real_run`, `::test_a_post_ladder_skip_shows_the_bound_not_the_equality` and the re-baselined `tests/tier2/test_scan_counters.py::test_ingest_dry_run_key_superset` (0,0,0,0 → 1,1,0,0) and `tests/tier2/test_scan_once_per_run.py::test_tree_run_resolves_each_storage_once` (0,0,0,0 → 1,0,0,0 — the same superseded clause in a second place the 2.7 spec's Code Map did not enumerate). |
| FR-31 | 2.7 | 2026-08-21 | The end-of-run summary of a `--dryrun` run reads `DRY-RUN: {count} folders scanned — no changes were made` instead of `{count} folders scanned` (real runs unchanged). Edited identically in both commands, so it also reaches Slack through `CustomLogger`. Pinned by `tests/tier2/test_dry_run_purity.py::test_summary_line_is_labelled_under_dryrun` and, for symmetry, `tests/tier1/test_commands_in_sync.py::test_handle_sources_identical`. |
| FR-36 | 2.5 | 2026-08-21 | An import response carrying no `jobId` is counted `failed`, never `ingested`. Pre-2.5 `import_file` fell through to an unconditional `result["ingested"] = True`, and `_import_multi_component` returned `True` whatever the response held — so a clip with a NULL `job_id` and no import job could be reported ingested. Pinned by `tests/tier2/test_ingest_discipline.py::test_multi_component_import_without_a_job_id_is_not_an_ingest` and, through the real `import_file`, `::test_a_real_import_without_a_job_id_is_failed_never_ingested`. |
